# 安装与恢复异常

安装或恢复前，先通过 Gemini 的“文件 → 退出”退出客户端。保留完整错误信息；不要手动覆盖 `app.asar` 或删除备份来强行重试。

0.1.3 的 `status`/`diagnose` 将清单与备份分开报告：`statePresent`、`backupPresent`、`backupValid`。`backupIssue` 可为 `missing`、`hash-mismatch`、`invalid-file`、`unreadable`、`unregistered` 或 `incomplete-directory`。出现这些状态时不要把“补丁已安装”当成“可以安全恢复”。

运行时诊断 JSON 损坏会显示 `runtime.available: false`，不影响独立的备份/构建检查。正常重新加载后可能生成新记录；不需要因此删除原始备份。

## 更新本工具

在旧补丁仍有完整备份时，先执行 `node bin/gemini-zh.mjs restore`，成功后再执行新版本的 `install`。恢复会检查当前资源包和原始备份的摘要。不要用新版安装命令覆盖旧备份。

## 提示备份目录存在，但没有有效状态记录

这可能是安装中断，也可能是目录中已有其他内容。工具会停止，不会自动删除目录。

如果资源已是原版，`restore` 可能返回 `already-original` 和 `backupDirectoryRetained: true`。这表示没有改动客户端、残留目录仍需核对，不表示下一次安装会自动清理该目录。

1. 保留客户端 `resources/.gemini-windows-zh` 中的所有文件，另行复制到自己的安全位置；不要上传 Google 资源包或个人数据到公开 issue。
2. 运行 `diagnose`，记录是否仍为原版、是否有补丁以及摘要。只有状态记录完整、当前包与记录相符且原始备份校验通过时，才使用 `restore`。
3. 如果状态记录缺失、备份损坏或当前资源包另有改动，停止手动操作。可通过 Google 官方安装程序修复客户端，然后重新诊断。修复前保留备份以便核对。

## 提示客户端文件已经变化

可能有自动更新或其他程序同时修改文件。工具会保留现有文件和备份。退出客户端，确认更新结束后重新诊断；不同构建需要单独验证，不能强行套用补丁。

恢复入口仍会校验当前 EXE 签名、Fuse、构建和资源结构。当前程序来源异常、原地更新或包损坏时，即使备份存在也可能拒绝操作；不得将旧 ASAR 自动配给新 EXE。应保留文件并通过官方安装程序修复/核对版本。工具不会自动回退修改磁盘上保留的旧版本目录。

恢复成功后，如果备份目录含有本工具不认识的文件，工具保留该目录并返回 `backupDirectoryRetained: true`。请自行核对其中内容，工具不会删除无关文件。
